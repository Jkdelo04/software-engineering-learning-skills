# stuck-what-next

Raise credible security issues first. Use the prompt and existing evidence to find the blocker. If two materially different actions remain plausible, ask one focused question before recommending a path. Include the catalog either way.

When the blocker is clear, give one action the learner can take now and, when helpful, recommend at most one coaching skill. For unclear invite permissions, for example, ask the learner to write down who may invite whom, then recommend `$secure-design`.

| Skill | When to use it |
| --- | --- |
| `$stuck-what-next` | Choose a next step when unsure. |
| `$learn` | Learn a concept or syntax. |
| `$hint` | Get one clue for a specific blocker. |
| `$secure-design` | Plan a feature that crosses a trust boundary. |
| `$security-review` | Review existing work for security risks. |
| `$system-design` | Compare designs and pick boundaries. |
| `$debugging` | Investigate behavior you did not expect. |
| `$test-first` | Express one behavior as a test. |
| `$safe-change` | Change unfamiliar or weakly tested code. |
| `$test-me` | Practice recall or application. |
| `$technical-interview` | Practice a technical interview using your codebase. |
| `$setup-learning-repo` | Install the toolkit after approving the file plan. |
| `$override` | Explicitly delegate one named task for this turn. |

Leave the next action and skill choice with the learner.
